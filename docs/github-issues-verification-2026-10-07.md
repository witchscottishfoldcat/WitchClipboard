## #1：已有独立迷你面板快捷键，缺少主快捷键模式设置

- `src-tauri/src/main.rs:47`：`MINI_HOTKEY` 固定为 `Alt+M`；`:914` 注册；`:956` 分派到 `toggle_mini_window`。
- `src-tauri/src/main.rs:952`：主快捷键分派到 `toggle_main_window`，不根据设置切换面板类型。
- `src-tauri/src/model.rs:230`、`src/components/SettingsSheet.tsx:437`：只有 `trayOpensMini` 控制托盘点击，没有主快捷键面板模式字段。

现有用户可用 `Alt+M` 快速打开迷你面板，并关闭“单击托盘弹迷你预览面板”，使托盘单击打开完整面板。Issue 所要求的“可配置的主快捷键默认打开迷你面板”仍未实现。这是功能增强请求，不宜概括成项目完全没有迷你面板快捷键。

## #2：两种面板都会主动获取焦点

`src-tauri/src/main.rs:682–683` 在显示窗口后调用 `window.set_focus()`，完整面板和迷你面板共用此路径。新建窗口也调用同一路径。代码没有不夺取焦点的配置或窗口策略。

当前交互还依赖 WebView 接收搜索、方向键和 Enter。实现该建议时，需要同时设计保持原应用焦点时的键盘路由，单纯删去 `set_focus()` 会影响这些操作。

## #3：事件绑定完整，失效发生在目标窗口的焦点状态

前端链路已接通：`src/components/MiniRow.tsx:63` 的双击与 `src/MiniApp.tsx:129` 的 Enter 都调用 `api.paste(id)`；Tauri 适配器调用 `paste_item`。命令接收发起调用的 `WebviewWindow`，权限配置也覆盖 `main` 和 `mini`。没有发现“双击/回车未绑定”或“固定隐藏错误面板”的缺陷。

为避开电脑上已安装版本的单实例锁和热键注册，使用当前源码生成了临时诊断副本，仅调整应用标识、测试热键、模块路径，并增加目标 PID 与 `SendInput` 返回值的日志；业务粘贴逻辑保持原样。使用独立临时数据目录和当前 Vite 渲染层，测试对象为 Windows 记事本，内容为 24 字符的 `WCC_ISSUE3_TEST_20261007`。

| 对照条件 | 操作 | 结果 |
| --- | --- | --- |
| 含 Alt 的测试呼出组合，返回后记事本显示菜单访问键提示 | 迷你面板回车、双击 | 均未增加文本；剪贴板内容为测试标记 |
| 记事本仍在菜单焦点状态 | 手动 Ctrl+V | 同样未增加文本 |
| 重新点击编辑区 | 手动 Ctrl+V | 文本从 24 增至 48 字符 |
| 正常编辑焦点，以不含 Alt 的测试组合呼出 | 迷你面板回车 | 从 48 增至 72 字符 |
| 正常编辑焦点，以不含 Alt 的测试组合呼出 | 迷你面板双击 | 从 72 增至 96 字符 |
| 在记事本按 Alt 进入菜单焦点，再以不含 Alt 的组合呼出 | 迷你面板回车 | 仍为 96 字符；面板收起，文本未粘贴 |

最后一项的诊断日志确认：保存的目标 PID 是测试记事本；Ctrl 按下、V 按下、V 松开、Ctrl 松开四次 `SendInput` 均返回 `1`。因此这个失败条件不是条目未写入剪贴板、目标进程记错或 Windows 拒绝注入，而是目标窗口虽然恢复到了前台，编辑区没有处于能接收粘贴的焦点状态。

相关代码在 `src-tauri/src/platform.rs:616`、`:638`、`:658`：恢复窗口并等待其成为前台，只等固定时间后发键，没有核对或恢复编辑控件的焦点。`restore_and_paste` 在这种情况下仍返回成功；另外 `send_key_event` 在 `:766` 忽略 `SendInput` 返回值，其他真正的注入失败也可能被误报成功。本次成功与菜单状态失败中的注入返回值都是 `1`，后者不是由这个返回值检查缺口造成的。

另一个待复现的风险是托盘目标记录：`src-tauri/src/main.rs:535` 仅排除自身进程的窗口，若托盘点击时前台是任务栏或托盘溢出窗口，就可能记录错误的粘贴目标。本次没有完成真实托盘点击的复现，不能将其当作已确认原因。
