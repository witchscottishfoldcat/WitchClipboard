# 修复与补齐计划（2026-09）

综合两类问题排期：**核心管线缺陷**（正确性与健壮性，直接影响用户可感知的行为）与**功能补齐**（产品能力差距，按影响力排序）。

## 通用纪律

- **R1 注释纪律**：所有新增/修改的代码注释只描述问题、不变量与实现理由本身，**不提及任何参考项目、竞品或对比来源**。文档与 README 同理。
- **R2 验证纪律**：每个里程碑收尾跑 `npm run selftest`、`npm run selftest:system-clipboard`、`npm run typecheck`。涉及剪贴板采集/粘贴路径的改动必须补充对应自检断言。
- **R3 迁移纪律**：所有触碰数据库 schema 的条目（F-13、F-14、F-19、F-20）需要：版本化迁移脚本、迁移前自动备份 `clipboard.db`、验证从备份回滚的路径实际可用。

## 里程碑 1：采集管线健壮性（建议 1.8.1）

> **状态（2026-09-14）**：F-01 ~ F-05 已完成。Rust 自检 39 项全部通过（含新增 8 项单测）；系统剪贴板 E2E 因开发机存在运行中的实例未执行，发布 1.8.1 前补跑 `npm run selftest:system-clipboard`。

全部是小改动，但保护的是「一条都不丢、敏感内容不误收」的核心承诺。

### F-01 读取失败不再永久丢条目
- **问题**：监听线程先消费序列号再读取，`read_clipboard_update` 任一步失败（剪贴板被其他程序短暂占用等）返回 `None` 后直接跳过，该条剪贴记录永久丢失（`src-tauri/src/main.rs:326-344`）。
- **改法**：把「跳过」与「暂时失败」区分开（返回值改枚举 `Saved / Skip / TransientError`）；`TransientError` 时回滚 `last_sequence` 并做 2 次退避重读（10ms 间隔）。剪贴板是共享资源，打开/取数失败是常态而非异常。
- **验收**：重读决策逻辑抽成纯函数加单测；正常路径走既有 E2E。
- **工作量**：S

### F-02 事件窗口合并读取（消除敏感标记竞态）
- **问题**：收到 `WM_CLIPBOARDUPDATE` 立即读取。写方（如密码管理器）通常先写内容、后补排除标记，立即读取会在标记就位前把敏感内容收进库。此外一次多格式复制会触发多次事件，每次都全量重读，仅靠 hash 去重兜底。
- **改法**：监听线程收到首个事件后用 `recv_timeout(100ms)` 排空后续事件，写方完成全部格式写入后再读一次。注释按 R1 只写不变量：「内容格式与排除标记可能分多次 `SetClipboardData` 写入，必须等事件窗口静止后读取」。
- **验收**：排空逻辑单测；手动用设置了 `CanIncludeInClipboardHistory` 的场景验证不误收。
- **工作量**：S

### F-03 「允许进入历史」标志按值语义判断
- **问题**：`CanIncludeInClipboardHistory` 是 DWORD 值语义：0 = 排除，非 0 = 显式允许。当前实现只检查格式存在性（`src-tauri/src/platform.rs:52-56, 364-370`），显式写「允许」的复制会被误判为敏感而跳过。
- **改法**：该格式存在时打开剪贴板读取 DWORD，仅值为 0 才跳过；其余两个标志维持存在性判断。
- **验收**：单测覆盖 0 / 非 0 / 不存在三种取值。
- **工作量**：S

### F-04 文件剪贴板原生读取加重试
- **问题**：`ClipboardGuard::open()` 单次 `OpenClipboard`，竞争失败即返回 `None`，文件复制被降级记成路径文本（`src-tauri/src/platform.rs:444-446, 455-459`）。
- **改法**：加 5 次 × 5ms 的打开重试（与底层剪贴板库自身的重试节奏对齐）。
- **验收**：既有 CF_HDROP E2E 不回归。
- **工作量**：S

### F-05 来源归因改用剪贴板所有者
- **问题**：来源程序取读取时刻的前台窗口（`src-tauri/src/main.rs:207`）。复制后快速切窗、或后台程序写入剪贴板时归因错误——「按来源搜索」是核心功能，归因必须准。
- **改法**：优先 `GetClipboardOwner()` → 窗口线程 → 进程名；所有者为空或属于 UWP 代理进程（RuntimeBroker）时回退前台窗口。
- **验收**：E2E：后台写入 + 快速切窗两个场景归因正确。
- **工作量**：S–M

## 里程碑 2：粘贴管线可靠性（建议 1.9.0）

### F-06 最小化的目标窗口先恢复
- **问题**：`restore_and_paste` 无 `IsIconic` 检查（`src-tauri/src/platform.rs:412-439`）。目标最小化时 `SetForegroundWindow` 可能返回成功但窗口仍在任务栏，Ctrl+V 灌进不可见窗口。
- **改法**：`IsIconic(target)` 为真先 `ShowWindow(SW_RESTORE)`。
- **工作量**：S

### F-07 前台恢复补强制手段
- **问题**：目前只有裸 `SetForegroundWindow` 重试两次。面板未抢到前台的状态下（后台唤出、看门狗路径）恢复会直接失败返回 `focus-failed`——这与已知的「面板拿不到焦点」是同族问题。
- **改法**：恢复序列升级为：保存并临时清零 `SPI_SETFOREGROUNDLOCKTIMEOUT` → 当前前台线程不是自己时 `AttachThreadInput` 挂接 → `BringWindowToTop` + `SetForegroundWindow` → 解除挂接并还原超时。所需 API 均在已启用的 windows-sys feature 内。
- **验收**：自检断言 + 手动验证「面板从未获得焦点」场景粘贴仍成功。
- **工作量**：M

### F-08 激活完成后再发键
- **问题**：固定 sleep 60ms 后发 Ctrl+V（`platform.rs:426`），重负载应用切换慢时按键可能早到。
- **改法**：轮询 `GetForegroundWindow() == target`（上限 ~250ms，10ms 步进），确认后立即发键；替代固定 sleep。
- **工作量**：S

### F-09 提权目标检测与显式报错
- **问题**：向管理员窗口粘贴时模拟按键被 UIPI 静默拦截，用户看到「无反应」。完整提权辅助进程方案成本高，先做检测与提示。
- **改法**：粘贴前 `OpenProcess` + `GetTokenInformation(TokenElevation)` 判定目标提权（windows-sys 需补 `Win32_Security` feature）；提权则返回明确错误码，UI 提示「目标窗口以管理员运行，无法自动粘贴，已复制到剪贴板，请手动 Ctrl+V」。
- **工作量**：M

### F-10 扫描码按键注入（可选）
- **问题**：`keybd_event` 虚拟键码对读取硬件扫描码的应用（部分终端、嵌套远程会话）兼容性欠佳。
- **改法**：改 `SendInput` + `KEYEVENTF_SCANCODE`（`MapVirtualKeyW` 转换）。做完 F-07/F-08 后评估是否仍有必要。
- **工作量**：S

## 里程碑 3：监听与存储保障（并入 1.9.0 或 1.9.1）

### F-11 采集监听存活看门狗
- **问题**：`AddClipboardFormatListener` 在会话事件（远程桌面重连、锁屏策略变化、剪贴板服务重启）后可能静默失效，失效即无声停止采集且无任何感知。
- **改法**：每 5 分钟自检一次：持 `clipboard_gate` 向剪贴板写一个私有注册格式（借既有 own-write 门控跳过入库），3 秒内未收到事件则判定监听死亡，重建消息窗口并重新注册。`start_clipboard_notifications` 的 `OnceLock` 单例结构需要改成可重启句柄。
- **验收**：自检模拟「事件通道关闭 → 看门狗重建成功」。
- **工作量**：M

### F-12 本地条目大小上限
- **问题**：本地采集无大小上限，复制超大文本/图片会全量入库，库膨胀且 UI 卡顿（跨设备路径已有上限，本地没有）。
- **改法**：设置项 `max_item_bytes`（默认建议 20 MB）；文本与图片 PNG 编码后超限则跳过并记日志。文件条目只存路径，不受影响。
- **工作量**：S

## 里程碑 4：高效生产力功能（1.9.x–2.0，按影响力排序）

### F-13 条目级持久热键（优先级最高）
- **价值**：把常用条目（签名、常用片段）绑到全局热键，是重度用户留存的核心能力；当前只有前 9 条快粘。
- **改法**：`items` 表加 `hotkey` 列（可空、唯一索引）+ 版本化迁移；启动与变更时经 global-shortcut 插件按 `item:<id>` 注册；按下即加载条目写剪贴板并粘贴到记忆目标；条目删除/清理时注销热键；设置 UI 提供「设定热键」入口，检测与面板热键和其他条目热键的冲突。
- **验收**：R3 迁移纪律；E2E：设定→全局触发→粘贴→删除条目后热键释放。
- **工作量**：M

### F-14 层级分组（片段库）
- **价值**：标签+置顶撑不起「片段库」工作流；需要可嵌套分组、组内整理。
- **改法**：新增 `groups` 表（id / parent_id / name / sort）+ `items.group_id`；导航区支持组树、进入组视图、条目移动到组；搜索默认当前组、可选全局。
- **验收**：R3；迁移后旧数据的默认分组视图与现行为一致。
- **工作量**：L

### F-15 多选批量粘贴
- **改法**：列表支持 Ctrl/Shift 多选；Enter 对选中项按列表顺序逐条「写入+粘贴」，条目间插入可配置间隔；混合类型按各自类型写入。
- **工作量**：M

### F-16 粘贴变换
- **改法**：条目菜单加「粘贴为」：纯文本 / 大写 / 小写 / 首字母大写 / 句首大写 / camelCase / 去首尾空白；渲染层完成文本变换后走「写原文+粘贴」命令变体；中文文本的大小写项自动置灰。
- **工作量**：S–M

### F-17 条目导入导出
- **改法**：选中条目导出为单一归档（文本 + 图片 blob，导出明文需显著警告与确认）；导入按内容 hash 去重合并。
- **工作量**：M

### F-18 从列表拖出到其他程序（可行性先行）
- **注意**：Tauri 2 无现成「拖出数据到系统」API，需要自实现 OLE `IDropSource`/`IDataObject`（COM）。先做 1 天可行性验证再决定排期。
- **工作量**：L（含验证）
